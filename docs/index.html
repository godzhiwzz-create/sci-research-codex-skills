01 / THE TOOLKIT

一个具体问题，
一个清晰入口。

不必同时调用全部 8 个 Skill。研究状态与稿件写作分开负责，其余模块按任务进入；已有项目规则和目录结构始终优先。

01研究状态负责人↗

接续项目，
判断下一步。

找回当前问题、证据与缺口。先核验最近先例，再决定是否投入；讨论不自动变成实验。

sci-research-managerState & evidence
02稿件生命周期负责人↗

保持主线，
写到恰当的深度。

从初稿、打磨到修订与校样。局部改稿不触发全稿重审，文字变强不等于证据升级。

academic-manuscript-writingManuscript & mainline
03文献来源↗

查新，也能只入库一篇。

验证身份与版本、去重、增量登记。围绕具体疑点检索，不重启全领域搜索。

sci-literature-managerSource packet
04论文阅读↗

把机制和证据读明白。

小问题直达原文；完整精读再生成理解包、方法图与图表说明。

sci-paper-readerReading handback
05实验记录↗

让一次实验真正闭环。

固定协议，链接原始结果，维护实验卡与索引。只执行已授权的工作。

sci-experiment-managerExperiment card
06证据核验↗

让每个数字经得起追问。

回到原始结果和协议核对冲突。只读审计，明确支持什么、不支持什么。

sci-result-auditorAudit findings
07论文配套↗

把稿件和交付物对齐。

维护 claim map、图表计划、要求缓存与文件清单，不擅自改写论文主线。

sci-paper-managerPaper artifacts
08资产维护↗

整理文件，也守住证据。

检查留存、归档和迁移风险。保留来源与时间，未经授权不移动或删除。

sci-asset-managerAsset review
专门模块可以直接完成窄任务，只有状态或主线需要集成时才交接。完整职责边界 ↗

02 / RIGHT-SIZED RIGOR

严谨，
不等于每一步
都很重。

需要多深，就进入多深。
这是五种任务强度，不是五步必经流程。

了解按需工作流 ↗
◇

讨论一个想法 DISCUSS

回答眼前的问题，指出可检验差别。不自动建档、下载或远端执行。

⌕

做一次定向查新 VERIFY PRIOR ART

核验最近先例，说明实质重合与尚未测试的差别，不轻率否定整个方向。

⊙

进行最小探索 PROBE

在已有授权内，用小而固定的协议区分竞争解释，为下一次决定提供信息。

⊞

开展正式实验 EXPERIMENT

保留完整协议、公平对照、统计标准与原始证据，完成实验记录闭环。

✓

准备投稿审计 AUDIT

对冻结材料做完整一致性检查。发现缺口就明确报告，不自动提交。

复用未变上下文记录按事件更新原始证据优先保留有效负结果

04 / GET STARTED

先预览，
再安装。

从一个需要的 Skill 开始。安装器默认只展示计划，不改文件；已有安装不同会先停止，显式升级才会备份并替换。

  • Python 3.10+，无第三方依赖
  • 支持选择安装与整个旧目录备份
  • 安装后重新加载 Codex Skill 列表
完整安装与升级说明 ↗
TERMINALmain · 安全安装器
01 / 克隆仓库并预览
git clone https://github.com/godzhiwzz-create/sci-research-codex-skills.git
cd sci-research-codex-skills
python3 scripts/install_skills.py --skill sci-research-manager
02 / 确认预览后，手动执行
python3 scripts/install_skills.py --skill sci-research-manager --apply

复制不会执行命令。只有 --apply 才写入安装目录。
